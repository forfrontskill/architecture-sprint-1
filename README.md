# Задание 1: Разделение на микрофронтенды

## Шаг 1. Проведение первичного анализа

Сайт предоставляет страницу с фотографиями мест, которые посетили пользователи.

**Основной функционал:**
1. Регистрация, авторизация, редактирование профиля, редактирование аватара.
2. Отображение карточек с местами, которые посетили пользователи.
3. Возможность лайкать места других пользователей.
4. Возможность открыть фотографию места.
5. Удаление карточек, принадлежащих пользователю.
6. Добавление новых мест.

**Текущий стек реализации:**
- **Backend:** реализован на JavaScript, в качестве фреймворка используется Express.
- **Database:** MongoDB.
- **Frontend:** монолит. Используются JavaScript и библиотека React, для управления состоянием — Context API. Сборка осуществляется с помощью Webpack. Для стилизации компонентов применяется методология БЭМ.

## Шаг 2. Определение бизнес-функций для команд

- **Команда 1:** работа с регистрацией и профилем, поддержка основного модуля (main), а также модуля контекста.
- **Команда 2:** работа с лентой мест.

---

## Шаг 3. Выбор метода реализации

Выбрана стратегия **«вертикальной нарезки»** для снижения зависимости от общих компонентов. В данном проекте такой подход приведёт к дублированию компонентов, но снизит связанность модулей. Исключение — общий контекст, который вынесен в отдельный модуль для подключения в другие. Однако, поскольку доработка контекста не требуется, это не создаст повышенной нагрузки на разработку и не увеличит связанность.

- **Метод интеграции:** Run time (важно развёртывать модули независимо).
- **Композиция микрофронтендов:** клиентская.

---

## Шаг 4. Выбор инструментов создания микрофронтендов

- **Module Federation** — позволяет загружать фрагменты кода по требованию, обеспечивает гибкость и оптимизацию общих ресурсов.
- **Сборщик Vite** — современный, поддерживаемый и оптимизированный инструмент для сборки.

## Шаг 5. Межмодульное взаимодействие

Реализована модель **«глобального состояния»**, так как она уже присутствовала в проекте и на первом этапе проще всего интегрируется.

## Структура системы

Система разделена на следующие модули:

1. **main-microfrontend**  
   Основной проект (Host), выполняющий маршрутизацию и загрузку модулей. Содержит логику управления основной страницей.
2. **auth-microfrontend**  
   Регистрация, аутентификация, авторизация. Основные компоненты: `Register`, `Login`. Главный объект — страницы входа и регистрации.
3. **profile-microfrontend**  
   Профиль пользователя. Главный объект — профиль пользователя.
4. **place-list-microfrontend**  
   Лента мест. Главный объект — карточка места.
5. **shared-microfrontend**  
   Общий пользовательский контекст, который подгружается в необходимые модули.

### Развитие

- Вынесение логики работы модулей из `main` в дочерние компоненты с использованием контекста.
- Оптимизация загрузки общих ресурсов.
